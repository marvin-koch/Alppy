WHAT'S INSIDE
=============

Each feature folder has 3 documents:

1️⃣ README.md
   ├─ §1: What it does (2–3 paragraphs + ASCII diagram)
   ├─ §2: Invariants (load-bearing rules)
   ├─ §3: Module map (which files own what)
   ├─ §4: How to extend (checklist for developers)
   ├─ §5: Privacy & safety
   └─ §6: Testing strategy (one test per invariant)
   
   → Provides: Contract + rules + module ownership
   → Read time: 15 minutes

2️⃣ architecture.md
   ├─ Component diagram
   ├─ Data flow (input/output classes)
   ├─ Component details (pseudocode for each piece)
   ├─ Edge cases (what happens when X, Y, Z)
   └─ Companion links
   
   → Provides: How components talk + visual reference
   → Read time: 20 minutes

3️⃣ decisions.md
   ├─ D1: [Decision title]
   │  ├─ Background (why this was needed)
   │  ├─ Considered alternatives (3 options; why 2 rejected)
   │  ├─ Tradeoff (benefits & costs)
   │  └─ How this reinforces Invariant I-X-YY
   ├─ D2: [Next decision]
   ├─ D3: ...
   └─ Policy change warnings (don't do this, here's why)
   
   → Provides: Why each design choice was made
   → Read time: 5 minutes per decision


HOW TO USE THIS

│  ├─ Find: grep -r "# I-sheets-01" alppy/
│  └─ Test: pytest tests/ -k test_I_sheets_01 -v
├─ Write: tests first
├─ Code: with invariant comments (# I-sheets-01)
└─ Time: 30 minutes

I'm a Code Reviewer:
├─ Ask: "Which invariants does this PR touch?"
├─ For each: Find enforcement, find test, verify code respects it
├─ Run: pytest tests/ -k test_I_ -v
└─ Time: 15 minutes

I'm curious about a design choice:
└─ Read: docs/features/[feature]/decisions.md D[number]
└─ Time: 5 minutes


WHAT'S PROTECTED
================

Every core feature has:

1. Load-bearing rule (Invariant)
   Example: "No AI-generated exercise reaches paper without approved_at"

2. Code enforcement
   Example: if sheet.approved_at is None: raise PermissionError("I-sheets-01")

3. Test verification
   Example: pytest test_I_sheets_01_unapproved_rejected()

4. Decision explanation
   Example: docs/features/sheets/decisions.md D1–D5

When an LLM wants to modify something:
  ✓ Reads §2 Invariants
  ✓ Tries to violate one
  ✗ Test fails
  ✓ Reads why (decisions.md)
  ✓ Realizes: "Oh, this matters for safety/fairness/privacy"
  ✓ Doesn't break it

Result: Core features are protected by:
  - Automated tests
  - Human-readable explanations
  - Design rationale
